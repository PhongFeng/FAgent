# 开源工具链方案

## 选择原则

必须项先限于 Godot 标准版和 Git。Python、素材工具、测试框架、模型运行时按实际任务加入；不要求用户安装全部工具。工具安装包、版本和插件来源均应记录，升级后重跑相关验证。

Godot 标准版可使用 GDScript，常规工程不需要 .NET SDK。首版不依赖 C# 或自编译 GDExtension；若后续功能确实需要原生扩展，单独说明编译和分发成本。

## 工具选择

| 环节 | 建议工具 | 用途与边界 |
| --- | --- | --- |
| 引擎 | [Godot 标准版](https://godotengine.org/download/) | 编辑、运行、导入和导出；按目标平台评估渲染器 |
| 版本管理 | [Git](https://git-scm.com/)；大型二进制按需使用 [Git LFS](https://git-lfs.com/) | 保存工程与源资源；LFS 托管服务可能有配额和费用 |
| 2D 绘制 | [Krita](https://krita.org/)、[GIMP](https://www.gimp.org/) | 概念图、绘制、纹理处理；优先选择一款主工具 |
| 矢量素材 | [Inkscape](https://inkscape.org/) | 图标与矢量 UI；接入时验证 SVG 导入效果 |
| 3D 与动画 | [Blender](https://www.blender.org/) | 建模、绑定与动画；跨工具交换优先验证 glTF 流程 |
| 音效与音乐 | [Audacity](https://www.audacityteam.org/)、[LMMS](https://lmms.io/) | 音效编辑与音乐制作；分别检查插件、采样包许可 |
| 音视频处理 | [FFmpeg](https://ffmpeg.org/) | 音视频转换与演示录像处理；构建选项影响许可证要求 |
| 自动化 | [Python](https://www.python.org/)、Godot CLI | 环境报告、资源检查、日志整理与构建入口 |
| GDScript 静态检查 | [gdtoolkit](https://github.com/Scony/godot-gdscript-toolkit)（可选） | 格式与 lint；需验证与所选 Godot/GDScript 版本兼容 |
| 自动化测试 | Godot 测试场景；[GUT](https://github.com/bitwes/Gut)（按需） | 先覆盖关键规则；引入框架时固定兼容版本 |
| 本地模型运行 | [llama.cpp](https://github.com/ggml-org/llama.cpp)（可选） | 在硬件允许时接入本地模型；模型能力与权重许可另行评估 |

这些是候选工具，并非当前环境已安装或已集成的清单。AI 图片、音乐和语音生成不是首版前置依赖；可先使用自制占位资源，后续再接入有明确接口与许可的生成方案。

Agent 宿主独立选择。使用当前助手或其他商业模型可作为可选适配；若要求全流程开源、本地离线，需要另行验证宿主、推理后端、模型权重、依赖以及许可证，不能因引擎开源就宣称整套 AI 链路开源或免费。

## Godot 基线

在环境阶段执行并记录以下选择：

1. 核实标准版引擎的精确版本、可执行文件路径与对应导出模板。现有项目声明 `4.7`，应先确认所用引擎是否支持；若需更换版本，单独评估兼容性。
2. 根据目标平台选择 Compatibility、Mobile 或 Forward+，并在目标硬件验证。当前项目使用 Mobile，不自动修改。
3. 固定项目目录、主场景、输入动作、资源命名和保存路径。游戏类型确定后再选择 2D/3D 默认模板。
4. 用环境配置传入本机工具路径，不把个人绝对路径写入可分发 Skill。区分工程数据与 `user://` 运行存档。
5. 将 `.godot/` 等本地缓存排除在版本控制之外；保留需要提交的源文件和资源标识文件，由 Godot 维护资源关联。

本轮在 PATH 中未发现 Godot 命令，这不代表本机没有通过其他路径安装。尚未执行引擎导入、启动或导出检查。

## 验证层次

| 层次 | 能说明什么 | 不能替代什么 |
| --- | --- | --- |
| 文档与配置检查 | 路径、必需输入、依赖配置合理 | 引擎实际解析与运行 |
| 导入与解析 | 资源导入及脚本解析是否出错 | 真实交互与玩法正确性 |
| 无窗口运行与规则测试 | 关键脚本、状态转换、数据规则 | 画面、音频、输入和体感验证 |
| 图形运行与试玩 | UI、输入、画面、音频、核心循环 | 长时间性能和全部平台兼容性 |
| 导出包验证 | 指定平台的包可以启动并完成关键路径 | 其他未经测试平台的支持承诺 |

后续 CLI 适配可基于如下 Godot 4 命令形式；下列内容为示例，不是已执行的结果。实际命令用选定版本的 `--help` 核实，并由脚本收集退出码、标准输出和错误日志。

```text
godot --version
godot --headless --path godot/f-game --editor --import
godot --headless --path godot/f-game --quit-after 120
```

第三条需要主场景和可运行工程；`120` 是运行帧数，不能用来宣称通过了固定秒数的性能测试。无窗口模式也不能证明 GPU 渲染、声音或用户交互正确。导出阶段还需要匹配版本的导出模板和已配置的导出预设。

## 许可证与来源记录

首版为实际使用的每项第三方内容记录：名称、类型、作者、来源 URL、获取日期、许可证或授权凭据、修改情况、署名要求、允许的使用与再分发范围。

软件、插件、字体、音乐、采样包、模型与生成素材分别记录。来源不明确的资源可暂留开发记录，但在确认授权前不放入面向他人的模板或发布包。项目代码、文档、Skill 和自制资源的许可证也要明确；当前尚未选定仓库许可证。
